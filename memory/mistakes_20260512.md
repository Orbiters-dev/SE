# 오답노트 2026-05-12

## ① 장보고 sticky 작성 시 메모리 확인 누락 — 강한 교정

**상황**: 세은이 "지금껏 진척된 agent들 사항 n8n Operations Hub에 반영" 지시. 신규 sticky 7개 후보 중 장보고(daily-report) 포함. 내가 sticky 본문에 산출물을 "한국어 PDF — `.tmp/daily_report_YYYYMMDD.pdf`", 도구를 "`tools/build_daily_report_pdf.py`"로 적음.

**세은 반응**: "야 장보고는 pdf가 아니라 notion으로 보고하는 거라니까 .. 확씨"

**원인**:
- `.claude/skills/daily-report/SKILL.md` 본문이 여전히 PDF 중심으로 적혀있어서 그걸 그대로 sticky에 옮김
- 그러나 `memory/feedback_daily_report_notion_toggle.md` (2026-05-11) 에 "PDF X / 노션 toggleable heading_2 한 개 append" 강한 교정이 명시되어 있었음
- 또한 `feedback_seeun_daily_chronological_order.md`, `feedback_daily_report_today_decisions_not_rules.md` 등 노션 운영 룰이 메모리에 다수 적재
- 그럼에도 메모리 확인 단계를 건너뛰고 SKILL.md 기준으로만 작성

**룰**:
- **에이전트/스킬 관련 문서를 새로 만들거나 다른 곳(n8n sticky, 워크플로우 SOP 등)에 옮길 때 무조건 메모리(`memory/feedback_*`) 먼저 확인**. SKILL.md 보다 메모리가 더 최신일 수 있음.
- 특히 "산출물 형태"(PDF/노션/Sheets/Teams 등)는 운영 룰 영역이라 메모리에 있는 가장 최근 feedback 우선.

**재발 방지 — 이 작업류에 적용할 사전 체크**:
1. 대상 스킬 이름으로 `ls memory/ | grep -i <skill>` 검색
2. `feedback_*` 파일 전건 Read
3. SKILL.md와 메모리가 충돌하면 메모리 우선 + SKILL.md 수정 제안

## ② [부차] harness.py 깨짐 발견 → 수리

**상황**: n8n PUT 가드 + harness plan-gate가 묶여 있는데 `tools/harness.py`가 `from codex_auditor import CodexAuditor` ImportError로 죽어있어 plan-gate 자체가 불가능.

**원인**: `tools/codex_auditor.py`가 함수형으로 리팩토링됐는데 `tools/harness.py`(dual-provider 버전)는 클래스 import 시도 그대로. 실제 작동하는 건 `tools/harness_5stage.py`인데 hooks가 `tools/harness.py`만 호출.

**조치**: `tools/harness.py`를 `harness_5stage.py`로 위임하는 thin wrapper로 교체. 기존은 `tools/harness_legacy_dual_provider.py`로 백업.

**잔여**: `--gate plan` 인자가 codex_evaluator로 `build`로 잘못 전달되어 evaluator가 SKIP된 채 PASS 떨어짐. plan-gate 자체는 통과하지만 실제 plan 비평은 안 됨. 별건 수리 필요.

## ③ [구조 이슈] SKILL.md 와 메모리 불일치 잔존

`.claude/skills/daily-report/SKILL.md` 가 PDF 중심으로 적혀있는 한 다음에 또 같은 실수 가능. SKILL.md를 노션 중심으로 재작성 필요(세은 별도 요청 필요).
