## 2026-06-01 오답노트

### 1. .env 자체 확인 안 하고 외부 path 제안 (HIGH)

**상황**
- 메타 API 토큰 만료(HTTP 400) 발견 후 "세은이 페이스북 비즈니스 콘솔에서 신규 토큰 발급 후 .env 갱신 필요" 라고 답함
- 실제론 `.env` 에 `META_JP_ACCESS_TOKEN` 별도로 있었음 (US용 `META_ACCESS_TOKEN` 외에)

**세은 피드백**
- "이전 api는 meta에서 직접 따 온 거야 ?? 우회한 거야 ? 확인해 검증된 사실만 이야기해"
- "쌰갈 ;; 니가 env 가서 확인을 해"

**원인**
- META_ACCESS_TOKEN 만료 → 자체 fb_exchange_token 시도 실패 → 바로 "세은 발급" path로 점프
- `.env` grep 으로 다른 토큰 있는지 안 봄. CLAUDE.md "직접 파악 가능한 건 묻지 마" 룰 위반

**예방**
- 토큰 만료 / 자격 에러 시 첫 step = `.env` 전수 grep + `tools/` 코드 path + 메모리 (특히 session_*.md 의 토큰 인계 기록)
- "직접 발급 path" 제안 전 자체 자원 100% 소진

### 3. 일시적 fallback 본질 누락 (HIGH)

**상황**
- 메타 API 토큰 만료 → DataKeeper 캐시로 fallback 시도 → 5/30까지만 데이터 있음 확인
- 그 시점에 "DataKeeper로 채울 수 있다" 답변 시도

**세은 피드백**
- "아니 근데 어차피 토큰 갱신해야 되는 거 아냐 ?? 그걸 가져온다고 될 일이 아니라. 그건 일시적인 방편 아님;;;; ?"

**원인**
- DataKeeper도 같은 메타 API 토큰으로 cron 돌리는 인프라라는 인지 부족
- root cause (토큰 만료) 해결 없이 일시 우회로 보고 마무리 시도

**예방**
- Fallback 검증 시 = 그 fallback 인프라가 같은 root cause 영향 받는지 먼저 확인
- 일시 데이터 → 영구 해결 path 항상 명시

### 4. 시간 관리 / 세은 짜증 신호 무시 (MEDIUM)

**상황**
- 메타 토큰 검증 + ad-level fetch + best/worst 산정 + 노션 PATCH 진행 중
- 세은: "뭘 그렇게 계속 하는데? 니는 뭐가 그렇게 오래 걸리는데"

**원인**
- 토큰 받은 후 검증 → fetch → 계산 → PATCH 4단계 직렬. 보고 압축 없이 진행 알림 자주 안 함
- 세은 입장에선 "토큰 줬는데 왜 안 끝나" 신호

**예방**
- 큰 작업 4단계 + 시작 시 ETA 한 줄 ("토큰 검증 → fetch → 분석 → PATCH, 약 5분")
- 단계별 짧은 진행 알림 (한 줄)
