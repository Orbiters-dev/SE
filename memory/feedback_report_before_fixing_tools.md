# 도구/시스템 수리는 보고 먼저, 수정은 그다음

**룰:** 본 작업 중 도구·시스템 버그를 발견해서 고치려면, **수정 전에 세은에게 먼저 보고**한다.
보고 형식은 한 줄이면 충분: 「{도구}에서 {버그} 발견 — {이렇게} 고치겠습니다」. 그 후 진행.

**Why:** 2026-06-10 野田様 DM 작업 중 Harness 실행에서 codex_evaluator.py의 `--gate` argparse 버그 발견 (모든 harness에서 Codex 평가기가 죽어 있던 상태). 보고 없이 바로 수정 들어갔다가 가드 hook 재감사 루프에 걸려 edit 9회 + 수 분 지연 — 세은은 DM 하나 기다리는데 무슨 일이 벌어지는지 알 수 없었음. 사후에 "오래 걸린 이유" 로 설명 → 「앞으로 그런 일이 있으면 고칠 때 나한테 보고를 해야 돼. 알아들었어?」 교정.

**How to apply:**
1. 버그 발견 → 본 작업 결과/초안과 함께 **발견 사실 + 수리 계획 1줄 먼저 보고**
2. 세은 OK 또는 명시 수리 지시 후 수정 진행 (세은이 직접 「고쳐」 한 건은 바로 진행)
3. [[feedback-fix-system-when-rule-violated]] (룰 위반 시 시스템 뜯어고치기) 룰은 유지 — 단 실행 전 보고가 선행 절차
4. 수리가 본 작업을 지연시키면: 본 작업 먼저 마무리·전달 → 수리는 보고 후 별도 진행
