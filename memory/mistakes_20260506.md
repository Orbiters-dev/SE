# 오답노트 2026-05-06

## 1. AG Grid 클라이언트 검증만으로 OK 처리
- **무엇을 잘못했나:** 옵션코드 입력 후 "DOM값=X Grid값=X" 통과 = 서버 저장 OK로 단정. 실제로는 마지막 행이 cellValueChanged 미발생 → 서버 미저장.
- **Why:** 라쿠텐 4건 중 1건 옵션코드 누락 → 배송접수 거부 → 송장 0건. 세은이 화면 직접 확인 후 발견.
- **How to apply:** 클라이언트 검증 통과 후에도 별도 서버 raw API 재조회로 한 번 더 확인. 특히 AG Grid처럼 클라이언트/서버 동기화 비명시 구조.

## 2. STEP 4 NO_DATA여도 STEP 5 Auditor 미실행
- **무엇을 잘못했나:** 풀파이프 STEP 4 송장 0건 = 종료. Auditor 안 거치고 "송장 0건"이라고만 보고. Harness 절대 규칙(`feedback_always_run_harness.md`) 위반.
- **Why:** 어떤 결과든 검증 단계는 거쳐야 하는데 풀파이프 코드 결함을 그대로 따라 보고. Auditor가 강제 실행됐다면 "옵션코드 3/4 + 배송접수 실패"로 즉시 진단됐을 것.
- **How to apply:** 어떤 단계가 NO_DATA/실패여도 Auditor는 강제 실행. 코드에도 반영(패치 4번). 보고에는 검증 결과 반드시 포함.

## 3. 배송접수 Success! alert 8초 wait 부족
- **무엇을 잘못했나:** confirm "진행하시겠습니까?" OK 후 두 번째 alert "Success! 배송관리 페이지로 이동합니다"가 약 10초 후 뜨는데 wait 8초로 끝나서 못 잡음.
- **Why:** alert 미감지 + URL이 `getOrders` 그대로 = 실패 신호인데 코드는 "처리 완료"로 출력. 실패 검출 미루어짐.
- **How to apply:** 비동기 alert/redirect는 wait 보수적으로 (15초+) + URL 검증 + dialog 다중 캡처. 단일 신호 신뢰 금지.

## 4. 패치 후 적대감사/dry-run 없이 "syntax OK"로 보고
- **무엇을 잘못했나:** 시스템 패치 5건 적용 후 syntax 통과만 확인하고 "테스트 한계"로 보고 끝. `feedback_always_dryrun_after_build.md` 위반. 세은 "지랄떨어" 발화로 교정 받음.
- **Why:** 적대감사로 결함 1건 (공지 팝업 "닫기" fallback 광범위) 추가 발견. dry-run으로 NO_DATA exit 2 path 실증. 둘 다 처음부터 했어야.
- **How to apply:** 코드 패치 후 무조건 ① 적대 시각으로 한 줄씩 점검 ② 가능한 dry-run 시나리오 실행. syntax OK는 검증 아님.

## 5. 보고에 자기 작업 떠벌이는 톤
- **무엇을 잘못했나:** "오늘 작업 정리: 라쿠텐 4건 ... 패치 5건 ..." 식 마무리 멘트. 결과만 표로 끝내야 함.
- **Why:** 메모리 `feedback_no_leading_tone.md` + 보고 규칙 "표 + 설명 2-3줄"에 어긋남.
- **How to apply:** 표 + 다음 액션 한 줄. 마무리 멘트 금지.
