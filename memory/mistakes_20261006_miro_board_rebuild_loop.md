# 오답노트 2026-10-06 (Miro JP 퍼포먼스 보드 제작 — 세은 극대노 반복)

세은 다수 강한 교정("장난하나"·"미친놈"·"존나게 열받게"·"정신 못 차리네"·"이 쌰갈럼아"). 하루 종일 보드 리빌드 루프.

## 핵심 오답 패턴

1. **목표 "정답 레퍼런스" 있는데 안 받고 추측 빌드 반복.**
   세은이 원한 건 처음부터 특정 양식(김지아 "SBV 퍼널" 보드 = 구조+운영룰+변경관리). 근데 나는 레퍼런스 달라고 안 하고 **랜딩중심 → A/B 형식 난립 → 시계열**로 계속 추측 빌드하고 폐기 반복. 중반에야 최원준이 아티팩트(지아님 보드) 공유 → 그제야 정답 봄.
   **→ 교훈: 복잡한 시각 산출물은 "따라할 레퍼런스 있어요?" 먼저 묻고 확보·정독 후 그려라. 추측 2개 만들어 컨펌받기 < 정답 1개 보고 그리기.**

2. **레퍼런스의 US 전용 운영개념을 JP에 검증 없이 베낌.** (재발 패턴)
   지아님 보드 = Amazon **US** 극단깊이. 거기서 **보호구간·도전자슬롯·챔피언·소재토너먼트·E20·BEP(PPSU 3.89x)·$문턱**을 우리 JP Amazon 보드에 그대로 베낌. 세은 "이딴 우리가 안 쓰는 말은 치워"·"어디서 보고 따라하는 거야". US≠JP.
   **→ 양식(형태)만 차용. 수치·룰·용어는 JP 실측(삐삐 등). 미검증 US개념 금지.** [[project_miro_jp_perf_route_map]] 재발 — 예시(현석님 US) JP 오붙임.

3. **"나눠서" 지시는 끝까지 분리.** SP/SBV 따로(합침 교정), SS/PPSU 캠페인 따로(집행까지 분리), Meta 졸업→PPSU/Stainless Proven 풀 각각. 하나로 뭉치면 교정.

4. **랜딩(종착)은 전 판에 표기·통합.** 떼어 매달면 교정("따로 떼 놓으면 어떡해"). 노드에 통합하거나 종착 바로.

5. **내 판단 오류 인정.** "A(구조형)가 더 맞다" 단정 → 세은 "왜 A가 맞냐" → 실은 B(시계열/액션)가 지아님에 가까움. 레퍼런스가 답을 주면 추측 폐기.

## 2026-10-07 재발 (같은 보드 → Claude 아티팩트 전환 작업)

하루 뒤 같은 JP 워크플로우를 Claude 아티팩트로 옮기며 **동일 패턴 전부 재발** — 세은 "내가 이렇게 줄글로 줄줄 쓰랬어?"·"US 보드가 안 보이는 거야 뭐야? 너 안 봤어?"·"니가 하고 싶은대로 처 만들고 지랄"·"testing이랑 proven 차이를 어떻게 아냐".
1. **줄글로 씀** — 구조화된 형태(세은이 준 Claude 아티팩트 예시) 무시하고 산문으로 썼다 2회 교정.
2. **US 레퍼런스 또 안 봄** — 세은이 준 US 보드를 또 안 보고 내 맘대로 구성. (10-06 교훈 그대로 재발.)
3. **Testing/Proven 구조가 안 드러남** — 딱 보면 구조가 눈에 보이게 하라. (아래 운영구조 정본 참조.)
4. **PPSU(PPSU+Fliptop) vs Stainless 캠페인 분리·ABO/CBO 표기·Amazon 상품별 키워드 등록이 안 드러남.**
→ 교훈 불변: 복잡 시각/구조 산출물 = ①세은이 준 레퍼런스 먼저 정독 ②각 플랫폼 실제 운영방식부터 파악 ③구조(Testing/Proven·제품분리)가 한눈에 보이게. 운영 사실 정본 = [[reference-jp-meta-testing-proven-operating-structure]].
