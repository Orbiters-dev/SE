## 하드 룰 (위반 = 강한 교정 이력 있음)

1. **콘솔 조작 지시는 메커니즘 검증이 끝난 것만.** 검증 전이면 "확인 후 지시한다"고 말한다. 지시 후 번복 = 8/11 최다 사고 패턴.
2. **검증된 것만 말한다.** 콘솔 실물 > 리포트 CSV > 추론. 근거 등급: ①라쿠텐 실측(RPP·유입) ②소액 실측 ③가설(US 개념·방어 논리) — ③은 D+14 노출 0이면 퇴출.
3. **삭제 ≠ 제외.** 자동층은 미등록 검색어에도 배신한다(4개월 실측). 삭제 = 캡 제거일 뿐.
4. **등록이 실효 있는 경우는 3종뿐**: 브랜드어 ¥40 저가고정 · 낭비 캡 ¥40 · 목安 방향 고입찰(인상 단계). ¥96 등록 ≈ 캠페인CPC ¥100과 no-op — 실험 인프라(인상 손잡이·판정 대상 명시)로서만 의미.
5. **티어 = 등록 순서가 아니라 인상 순서.** T1부터 올린다.
6. **채널 교차 이식 금지** — 그 채널 근거 있는 키워드만 그 채널에.
7. **캡·브랜드어는 검색어가 실측 매칭된 모든 상품에** (상품×검색어 단위 상한 — 한 상품만 걸면 구멍).
8. 산출물·보고서에 "대표님" 문구 금지.
9. **캠페인 신설 직후 자동 타겟 잔존 스캔 필수** (양 플랫폼 공통 함정): AMZ = 콘솔이 수동 캠페인에 「키워드그룹(KEYWORD_GROUP_SAME_AS: category)」 타겟을 기본 체크로 끼워 넣음 — 8/25 실측: 세은 키워드 111개 대비 지출 66%·CPC ¥206 잠식(키워드 ¥119). `/sp/targets/list`(CT `application/vnd.sptargetingClause.v3+json`)로 확인. RKT = 카테고리 타겟 잔존(8/21 ¥166 사례). 신설 시 targets 조회 → 의도 밖 타겟 보고가 기본 동작.
10. **알림·판정·지시의 분모가 되는 설정값(예산·CPC·캠페인 수·타겟)은 당일 실측 후에만 사용.** 아래 「현재 상태」 블록과 메모리는 작성 시점 스냅샷 — 사람이 콘솔에서 수시로 바꾸는 값이라 알림 근거로 쓰면 오탐 낸다(8/27 사고: 8/11 값 ¥60,000으로 소진 🚨 발신, 실제 ¥110,000). 실측 경로: ①콘솔 실물 ②당일 데이터 역산(소진이 구예산 넘겨 계속되면 예산≠구값) ③세은 스샷. 셋 다 불가면 「현재값 확인 필요(마지막 확인 M/D ¥X)」로 라벨하고 알림 보류.
11. **⛔ 광고 계정 쓰기 조작 = 세은 명시 실행 지시 후에만** (8/27 무단 ENABLED 사고 — 「내가 언제 실행하라고 했냐」). 캠페인 on/off·예산·입찰·키워드 등록/삭제·타겟 변경 전부 해당. 조회(list)는 자유, 쓰기(PUT/POST/delete)는 승인 게이트. 「~하려고 해」「~해 보려고」 = 방향 공유 + 리포트 요청이지 실행 위임 아님 — 실행 위임은 「실행해」「네가 해」 명시 동사만. 기본 분업: 삐삐=설계·리포트·판정, 콘솔 실행=세은 매뉴얼. 쓰기 실행 시엔 실행 전 상태 스냅샷 필수(롤백 가능성 확보).

**판정 2-트랙 룰 (8/27 세은 확정 — 대표님 기준 채택)**:
- **효율 퇴출은 키워드당 ¥3,000~4,500($20~30) 소진 후에만.** 돈 안 써본 키워드를 효율 사유로 빼기 금지. 클릭 나오는데 전환 0이어도 이 소진량 전까지 판정 보류.
- **지출 ¥0(클릭 0) = 효율 트랙이 아니라 별도 트랙** — 원인은 수요 부재(검색량 실측으로 확인) or 입찰 부족. 수요 부재면 슬롯 회수, 수요 있으면 입찰 인상이 처방. "퇴출" 워딩은 효율 판정으로 읽히니 지출 0 건은 "교체 후보(수요 부재)"로 표기.
- 노출 0 판정은 리포트 부재(클릭 0)만으로 단정 금지 — 콘솔 노출수 확인이 확정 조건.
