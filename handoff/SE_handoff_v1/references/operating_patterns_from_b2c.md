# 운영 평가 패턴 reference (B2C 광고·매출 운영에서 추출 → B2B 도매·벤더 평가에 적용 가능)

원본은 메타 광고 / 라쿠텐 운영에서 굳힌 룰. 도매·유통 도메인 어휘로 추상화.

## 1. 매출 정의 = 정가 기준 (할인 후 X)

**원본**: 라쿠텐 매출 = `priceTaxIncl` (정가, 쿠폰·포인트 차감 전). RMS UI 「総売上」은 차감 후라 5~7% 작게 나옴.

**B2B 적용**:
- 거래선 평가 metric에 **gross sales (정가 베이스) vs net sales (할인·리베이트·반품 차감 후)** 항상 분리 보고.
- 한쪽만 보면 사고 — 정가만 보면 마진 착시, net만 보면 거래 규모 작아 보임.
- 신규 벤더 평가 시 "전년 매출" 받을 때 어느 정의인지 반드시 확인.

## 2. 평가 = 외부 시장 평균이 아니라 자기 풀 percentile

**원본**: Meta Off Rule 외부 시장 평균 CTR 사용 금지. 풀 자체 percentile (P20 하위) + 절대 기준 2중 게이트.

**B2B 적용**:
- 벤더 단가 평가 = 시장 평균이 아니라 **자사 벤더 풀 내 percentile** 기준.
- 「업계 평균 단가 대비 -10%」 라는 협상 카드보다 「자사 동일 카테고리 벤더 중 상위 30%」 가 fair.
- 평가 신호 단일 hit X. **풀 percentile + 절대 기준 (예: gross margin %)** 2중 hit 동시 발생 시에만 강한 조치.

## 3. Testing → Proven 졸업 게이트 (triple share)

**원본**: 신규 광고는 Testing pool. 졸업 조건 = 7일 풀 spend / clicks / conversion **3개 share 모두 ≥50%**.

**B2B 적용**:
- 신규 벤더 → 정식 거래선 승격 룰.
- 단순 「3개월 무사고」 X. **거래 비중 share** 로 평가:
  - 발주 건수 share / 거래 금액 share / 리드타임 준수율 share 3개 모두 일정 threshold 통과 시 승격.
- "거래 금액만 점유한 fake winner" 거르기 — 금액 share 높아도 납기 불량이면 fail.

## 4. Off 룰 = 시간 단독 X (성과 또는 delivery 실패 hit)

**원본**: WL 광고 「D+60 sunset」 단독 폐기. 광고는 3~6개월 운용 가정 + **성과 부진** 또는 **delivery 실패** hit 시에만 Off.

**B2B 적용**:
- 거래선 churn 판단 룰 — 「N년 안 거래했으면 자동 종료」 단독 X.
- 거래선 라이프사이클 가정 (예: 카테고리별 3~5년) + **성과 지표 부진** (매출 기여도 percentile P20 하위) 또는 **운영 실패** (불량률·납기 지연 임계 초과) hit 시에만 종료 결정.
- 시간만으로 자르면 회복 중 거래선 잘림.

## 5. 단위 분리 = ad 단위 X / 구조 단위 O

**원본**: Meta 광고 ad 단위 예산 조정 X. ad set / 캠페인 단위만.

**B2B 적용**:
- 평가·조정 단위 명확화. 개별 SKU 단가 흔드는 협상보다 **카테고리 / 거래선 전체** 단위 협상이 효율.
- 개별 발주 1건 단가만 보고 거래선 평가 X. 거래선 단위 누적 metric.

## 6. 통화·단위 가정 검증

**원본**: Meta JP 계정 통화 = KRW (JPY 가정 사고 났음). 작업 전 API로 실측 확인.

**B2B 적용**:
- 해외 벤더 견적·인보이스 통화 단위 자동 가정 X. 견적서 통화 표기 + 환산 환율 + 환산 기준일 3종 항상 확인.
- 시스템 화면에 표시되는 통화 ≠ 회계 처리 통화 가능성 (다중 통화 시스템).

## 7. 검증 = 도구 1개로 끝내지 X

**원본**: 빈 결과·0건·오류 = "없음" 단정 X. 도구 실패 가능성 신호. 두 번째 도구로 교차검증.

**B2B 적용**:
- 벤더 정보·재고·납기 등 시스템 1개 조회 결과만 신뢰 X.
- ERP / WMS / 벤더 포털 / 메일 회신 — 2개 이상 source 교차 일치 후 결정.
- 특히 「데이터 없음」 응답은 "원래 없음" vs "쿼리 오류" 구분 의무.
